本项目最终采用 **v2 模型方案** 作为论文主方案和系统默认部署方案：


```text

```

核心结论可以概括为：

> 本项目针对深度音频哈希检索中的哈希空间坍塌问题，构建了由 bit-balance、uniqueness、跨歌碰撞、同曲汉明距离和跨曲汉明距离组成的诊断体系，并通过同曲时间偏移正样本、SpecAugment、随机增益、量化损失、位平衡损失、hard negative mining 与 beta-tanh 退火训练策略进行修复。最终 v2 方案将跨歌曲平均汉明距离提升至 `61.65 bits`，接近 128-bit 随机二进制码理论期望 `64 bits`；全库唯一率达到 `94.85%`，跨歌完全碰撞码数降至 `706`，抽样跨歌 `0 bit` 距离为 `0`，同时业务层 Top-1/Top-5 均保持 `100%`。

论文中建议把 **v2** 作为主结果，把 **v0/v1/v3** 作为消融和演进对照：

- **v0**：原始基线，证明存在哈希空间坍塌。
- **v1**：第一轮反坍塌修复，同曲更紧，但死位仍在。
- **v2**：最终方案，零死位、低碰撞、跨歌距离接近理论期望。
- **v3**：中间路线消融，证明 bit-balance 不是线性可调，而存在硬阈值现象。

### 4.2 模型结构

模型定义见 `model.py`。

`AudioHashNet` 是 4 层 CNN + BatchNorm + ReLU + Pooling 的音频哈希网络：

| 模块 | 结构 |
|---|---|
| 输入 | Mel 频谱，形状约 `(1, 128, T)` |
| Conv Block 1 | `1 -> 64` |
| Conv Block 2 | `64 -> 128` |
| Conv Block 3 | `128 -> 256` |
| Conv Block 4 | `256 -> 256` |
| 池化 | `AdaptiveAvgPool2d((4, 4))` |
| 输出层 | `Dropout(0.5) + Linear(256*4*4, 128)` |
| 激活 | `tanh(beta * z)` |

训练时通过 beta 退火逐步逼近二值符号函数；推理时默认 `beta=1.0`。

### 4.3 检索结构

系统采用 Faiss 二进制索引：

```text
Faiss IndexBinaryFlat
哈希长度：128 bit
距离度量：Hamming distance
```

论文中可解释为：

> 128-bit 二进制哈希的理论随机跨样本平均汉明距离为 `128 / 2 = 64 bits`。因此，跨歌曲汉明距离越接近 `64 bits`，说明不同歌曲在码空间中越接近理想随机分散；同曲不同窗口距离应显著小于 `64 bits`。

## 5. 哈希健康诊断指标体系

诊断脚本：`evaluate_collapse.py`

| 指标 | 记号 | 含义 | 理想趋势 |
|---|---|---|---|
| bit-balance mean | A | 每一位为 1 的比例与 0.5 的平均偏差 | 越小越好 |
| bit-balance max | A | 最偏 bit 的偏差，接近 0.5 表示死位 | 越小越好 |
| uniqueness | B | 唯一哈希码数 / 总哈希码数 | 越高越好 |
| collision | C | 跨歌曲共享完全相同哈希码的码数 | 越少越好 |
| same-song Hamming | D | 同一首歌不同窗口之间的汉明距离 | 显著小于 64 |
| cross-song Hamming | E | 不同歌曲不同窗口之间的汉明距离 | 接近 64 |
| cross=0 | E | 跨歌曲抽样中 0-bit 完全相同的对数 | 应为 0 |
| 区分带宽 | cross − same | 跨曲均值减同曲均值 | 越大越好 |

论文写法建议：

> 单看业务 Top-1 命中率不足以发现底层哈希坍塌，因为多窗口投票可能掩盖局部撞码。因此本文额外建立哈希空间健康诊断体系，从 bit 分布、唯一码比例、跨歌碰撞和同/跨曲汉明距离四个层面评估模型是否具备可扩展的二进制检索能力。

### 6.2 表格解读

- **v0** 证明旧模型存在严重哈希空间坍塌：唯一率只有 `59.94%`，跨歌碰撞码多达 `14030`，最严重一个哈希码同时出现在 `413` 首不同歌曲中。

- **v3** 证明“中间超参”并不会自然得到最优折中：same 和 cross 都居中，但死位复发，碰撞数比 v2 多 `56%`。

## 7. 各版本实验历程

### 7.1 v0：原始基线，暴露哈希空间坍塌

旧版训练方式主要问题：

- 正样本构造过弱：`positive = anchor + 0.01 Gaussian noise`。
- 模型只需要记住局部微小扰动，不需要学习真实的同曲时间偏移不变性。
- 训练目标主要依赖 Triplet Loss，缺少量化损失和 bit-balance 约束。
- 学习率较保守，训练轮次较少。

v0 诊断结果：

```text
bit-dev mean        = 0.10
bit-dev max         = 0.50
死位数量             = 5
uniqueness          = 59.94%
跨歌碰撞码数          = 14030
最严重一码涉及歌曲数    = 413
same-song mean      = 16.79 bits
cross-song mean     = 60.39 bits
```

论文可写结论：

> 虽然 v0 的 cross-song mean 看似接近 64 bits，但大量完全相同哈希码和极低唯一率表明码空间存在局部严重坍塌。平均距离不能单独反映哈希空间健康度，因此必须同时考察 uniqueness 与 collision。

### 7.2 v1：第一轮修复，同曲更紧但死位仍在

v1 主要改动：

| 维度 | v1 做法 |
|---|---|
| 正样本 | 同曲不同时间窗口 |
| 数据增强 | anchor 与 positive 均增强 |
| 损失函数 | Triplet + quantization + bit-balance |
| hard negative | batch 内 hard negative mining |
| beta-tanh | `beta_end = 10` |
| margin | `8.0` |
| bit-balance 权重 | `0.05` |
| 训练轮次 | `15 epoch` |
| 最佳权重 | `hash_model_v1_epoch_15_best.pth` |

v1 诊断结果：

```text
bit-dev mean        = 0.149
bit-dev max         = 0.50
死位数量             = 5
uniqueness          = 88.70%
跨歌碰撞码数          = 1886
最严重一码涉及歌曲数    = 10
same-song mean      = 13.83 bits
cross-song mean     = 53.20 bits
Top-1 / Top-5       = 10/10 / 10/10
平均响应时间          = 9510 ms
```

v1 的意义：

- 相比 v0，跨歌碰撞从 `14030` 降到 `1886`，下降约 `86.6%`。
- same-song mean 从 `16.79` 降至 `13.83`，同曲窗口聚合更紧。
- 但是 bit-dev max 仍为 `0.50`，说明死位没有解决。
- cross-song mean 降到 `53.20`，不同歌曲之间没有充分拉开。

论文可写结论：

> v1 证明同曲时间偏移、复合损失和 hard negative mining 能显著缓解碰撞，但较弱的 bit-balance 约束无法消除死位，且过强的同曲压缩会牺牲跨曲分散性。

### 7.3 v2：最终方案，码空间健康度最佳

v2 调参依据：

| v1 问题 | v2 调整 |
|---|---|
| 5 个死位仍在 | `LAMBDA_BAL: 0.05 -> 0.15` |
| cross-song 被压到 53.20 | `MARGIN: 8.0 -> 6.0` |
| beta 后期过饱和 | `BETA_END: 10 -> 4` |
| anchor/positive 都增强导致偏离推理分布 | anchor 不增强，只增强 positive 和 negative |
| epoch 后期收益变小 | 训练轮次定为 10 |

v2 主要配置：

| 参数 | 数值 |
|---|---:|
| `NUM_EPOCHS` | `10` |
| `BATCH_SIZE` | `128` |
| `LEARNING_RATE` | `1e-4` |
| `MARGIN` | `6.0` |
| `LAMBDA_QUANT` | `0.1` |
| `LAMBDA_BAL` | `0.15` |
| `ALPHA_EASY` | `0.3` |
| `BETA_START -> BETA_END` | `1.0 -> 4.0` |
| Scheduler | `CosineAnnealingLR` |
| 最佳权重 | `hash_model_v2_epoch_10_best.pth` |

v2 全量诊断结果：

```text
ntotal              = 203200
code_size           = 16 bytes = 128 bits
bit-dev mean        = 0.0789
bit-dev max         = 0.2455
uniqueness          = 192738 / 203200 = 94.85%
跨歌碰撞码数          = 706
碰撞分布              = {2: 678, 3: 22, 4: 5, 6: 1}
最严重一码涉及歌曲数    = 6
same-song           = mean 16.92, median 14, std 11.87, min 0, max 74
cross-song          = mean 61.65, median 62, std 16.52, min 12, max 108
cross-song distance=0 = 0 / 5000 = 0.00%
```

v2 业务层结果：

```text
Top-1 命中 = 10/10 = 100.0%
Top-5 命中 = 10/10 = 100.0%
平均响应   = 9367 ms
```

论文可写结论：

> v2 不是单纯让同曲距离最小，而是在同曲距离可接受的前提下最大化码空间健康度。其 cross-song mean 达到 `61.65 bits`，已接近理论期望 `64 bits`；同时死位数量从 `5` 降为 `0`，跨歌碰撞从 v0 的 `14030` 降为 `706`，证明哈希坍塌得到实质性缓解。

### 7.4 v3：中间路线消融，证明 bit-balance 存在硬阈值

v3 设计动机：

> v1 同曲更紧，v2 码空间更健康。v3 尝试取中间超参，验证能否同时获得 v1 的 same-song 优势和 v2 的 cross-song/零死位优势。

v3 配置：

| 参数 | v1 | v2 | v3 |
|---|---:|---:|---:|
| `MARGIN` | `8.0` | `6.0` | `7.0` |
| `LAMBDA_BAL` | `0.05` | `0.15` | `0.10` |
| `BETA_END` | `10` | `4` | `6` |
| anchor 增强 | 是 | 否 | 否 |
| 训练轮次 | `15` | `10` | `10` |

v3 全量诊断结果：

```text
ntotal              = 203200
code_size           = 16 bytes = 128 bits
bit-dev mean        = 0.0995
bit-dev max         = 0.4974
uniqueness          = 188801 / 203200 = 92.91%
跨歌碰撞码数          = 1104
碰撞分布              = {2: 1038, 3: 47, 4: 12, 5: 5, 7: 2}
最严重一码涉及歌曲数    = 7
same-song           = mean 15.98, median 13, std 11.63, min 0, max 70
cross-song          = mean 59.66, median 60, std 17.35, min 6, max 110
cross-song distance=0 = 0 / 5000 = 0.00%
```

v3 业务层结果：

```text
Top-1 命中 = 10/10 = 100.0%
Top-5 命中 = 10/10 = 100.0%
平均响应   = 9524 ms
```

v3 结论：

- same-song mean `15.98` 介于 v1 和 v2 之间。
- cross-song mean `59.66` 也介于 v1 和 v2 之间。
- 但 bit-dev max 回到 `0.4974`，说明死位复发。
- uniqueness `92.91%` 低于 v2 的 `94.85%`。
- 跨歌碰撞码 `1104`，比 v2 的 `706` 多约 `56.4%`。

论文可写结论：

> v3 说明 bit-balance 不是线性折中指标，而存在硬阈值现象。当 `LAMBDA_BAL=0.10` 时，虽然 same/cross 两类距离指标位于 v1 与 v2 之间，但死位重新出现，导致唯一率下降和碰撞数上升。因此，v2 中 `LAMBDA_BAL=0.15` 的较强位平衡约束是必要的。

## 11. 方法演进总结

### 11.1 数据构造演进

| 版本 | 正样本构造 | Anchor 增强 | Positive 增强 | 负样本 |
|---|---|---|---|---|
| v0 | anchor + 0.01 白噪声 | 否 | 极弱白噪 | 随机不同歌曲 |
| v1 | 同曲不同 5s 窗口 | 是 | 是 | 随机不同歌曲 + hard negative |
| v2 | 同曲不同 5s 窗口 | **否** | 是 | 随机不同歌曲 + hard negative |
| v3 | 同 v2 | 否 | 是 | 随机不同歌曲 + hard negative |

论文可写：

> v2 以后保持 anchor 不增强，使 anchor 分布更接近实际查询音频；positive/negative 才进行随机增益、白噪声和 SpecAugment。这种非对称增强避免了训练分布同时漂移，使模型学习“原始查询与增强版本属于同曲”的不变性。

### 11.2 损失函数演进

最终训练目标可写成：

```text
L = α * L_triplet_easy
  + (1 - α) * L_triplet_hard
  + λq * L_quant
  + λb * L_balance
```

其中：

```text
L_quant   = mean((|h| - 1)^2)
L_balance = mean(mean_batch(h)^2)
```

含义：

- `L_triplet_easy`：常规随机负样本 triplet。
- `L_triplet_hard`：batch 内最近负样本，避免 easy negative 梯度消失。
- `L_quant`：推动连续输出靠近 `-1/+1`，提高二值化稳定性。
- `L_balance`：推动每一位在 batch 内 0/1 均衡，减少死位。

### 11.3 beta-tanh 退火

模型输出：

```text
h = tanh(beta * z)
```

训练期间 beta 从 `1.0` 线性增大到目标值，使输出逐渐接近符号函数。

| 版本 | `BETA_END` | 结果 |
|---|---:|---|
| v1 | `10` | 同曲更紧，但后期饱和，死位仍在 |
| v2 | `4` | 输出不过度饱和，配合强 bit-balance 消除死位 |
| v3 | `6` | 中间路线，死位复发 |

## 12. 为什么最终选择 v2

### 12.1 v2 相比 v0 的提升

| 指标 | v0 | v2 | 改进 |
|---|---:|---:|---:|
| uniqueness | `59.94%` | `94.85%` | `+34.91 pct` |
| 跨歌碰撞码数 | `14030` | `706` | `-94.97%` |
| 最严重一码涉及歌曲数 | `413` | `6` | `-98.55%` |
| 死位数量 | `5` | `0` | 完全消除 |
| cross-song mean | `60.39` | `61.65` | 更接近 64 |

### 12.2 v2 相比 v1 的优势

| 指标 | v1 | v2 | 结论 |
|---|---:|---:|---|
| same-song mean | **`13.83`** | `16.92` | v1 更紧 |
| cross-song mean | `53.20` | **`61.65`** | v2 明显更分散 |
| bit-dev mean | `0.149` | **`0.0789`** | v2 更均衡 |
| 死位数量 | `5` | **`0`** | v2 解决根因 |
| uniqueness | `88.70%` | **`94.85%`** | v2 更可扩展 |
| 跨歌碰撞码数 | `1886` | **`706`** | v2 更低碰撞 |
| 区分带宽 | `39.37` | **`44.73`** | v2 分离能力更强 |

虽然 v1 的 same-song 更低，但 v2 的综合优势更符合论文目标：**修复哈希空间坍塌，而不是只让同曲距离变小**。

### 12.3 v2 相比 v3 的优势

| 指标 | v2 | v3 | 结论 |
|---|---:|---:|---|
| bit-dev mean | **`0.0789`** | `0.0995` | v2 更均衡 |
| bit-dev max | **`0.2455`** | `0.4974` | v3 死位复发 |
| uniqueness | **`94.85%`** | `92.91%` | v2 更高 |
| 跨歌碰撞码数 | **`706`** | `1104` | v2 更低 |
| cross-song mean | **`61.65`** | `59.66` | v2 更接近 64 |
| 业务 Top-1 | `100%` | `100%` | 业务持平 |

论文可写：

> v3 作为中间路线并没有超过 v2，说明本任务中 bit-balance loss 的权重不是简单线性可调。低于某个阈值时，死位会重新出现，导致唯一率下降和跨歌碰撞增加。最终 v2 在码空间健康度上取得最佳平衡。

## 14. 论文章节写作建议

### 14.1 系统设计章节

可写内容：

- 使用 CNN 将 Mel 频谱映射到 128 维连续哈希向量。
- 使用动态中值二值化生成 128-bit 指纹。
- 使用 Faiss `IndexBinaryFlat` 进行汉明距离检索。
- 对每首歌前 30 秒进行 5 秒滑动窗口切片，构建多子指纹索引。
- 在线查询时同样进行窗口化和二值哈希，与离线建库保持一致。

### 14.2 方法改进章节

可写为五个改进点：

1. **同曲时间偏移正样本**：解决只学弱噪声扰动的问题。
2. **非对称数据增强**：anchor 保持原始分布，positive/negative 增强。
3. **Hard Negative Mining**：增强困难负样本训练信号。
4. **Quantization Loss**：提高二值化稳定性。
5. **Bit-Balance Loss**：消除死位，缓解哈希空间坍塌。

### 14.3 实验章节

建议表格顺序：

1. 数据规模表：`8000` 首、`203200` 子指纹、128-bit。
2. 指标定义表：bit-dev、uniqueness、collision、same/cross Hamming。
3. v0/v1/v2/v3 主结果表。
4. v3 epoch 选优表。
5. e2e Top-1/Top-5 业务验证表。

### 14.4 消融讨论章节

重点写：

- v1 说明“同曲更紧”不等于“码空间更健康”。
- v2 说明较强 bit-balance 是消除死位的关键。
- v3 说明中间参数不能线性折中，bit-balance 存在硬阈值。
- 业务层 Top-1 均为 100%，但底层哈希空间健康度决定系统扩展能力。

### 14.5 局限性章节

建议如实写：

- 当前实验主要覆盖纯净数字音频与一定白噪/SpecAugment 场景。
- 对真实手机外录、房间混响、扬声器-麦克风链路、设备底噪等物理域偏移仍需进一步增强。
- 后续可加入 IR 卷积、真实外录测试集、频带滤波、二次压缩等增强与评估。

可以直接改写为论文“实验结果分析”段落：

> 从实验结果看，原始 v0 模型虽然在部分查询中能够返回正确歌曲，但其底层哈希空间存在明显坍塌：全库唯一率仅为 `59.94%`，跨歌曲完全碰撞码达到 `14030` 个，最严重的哈希码同时出现在 `413` 首不同歌曲中。v1 通过同曲时间偏移、复合损失和 hard negative mining 将碰撞码降至 `1886`，并使同曲平均距离降至 `13.83 bits`，但仍保留 `5` 个死位，且跨歌曲平均距离下降到 `53.20 bits`，说明码空间仍被压缩。最终 v2 通过增强 bit-balance 约束、降低 beta 退火终点、调整 triplet margin 并采用非对称增强，使死位数量降为 `0`，唯一率提升至 `94.85%`，跨歌碰撞码进一步降至 `706`，跨歌曲平均汉明距离达到 `61.65 bits`，接近 128-bit 随机码理论期望 `64 bits`。同时，v2 在固定 10 首真实查询的端到端测试中 Top-1 和 Top-5 均为 `100%`，说明其在保持业务检索效果的同时显著改善了底层哈希空间健康度。

可直接改写为论文“消融实验结论”段落：

> v3 中间路线采用介于 v1 与 v2 之间的超参数配置，即 `MARGIN=7.0`、`LAMBDA_BAL=0.10`、`BETA_END=6.0`。实验表明，v3 的 same-song mean 为 `15.98 bits`，cross-song mean 为 `59.66 bits`，二者确实介于 v1 与 v2 之间；但其 bit-dev max 上升到 `0.4974`，死位重新出现，跨歌碰撞码也增至 `1104`。这说明 bit-balance loss 对死位消除存在阈值效应，并非简单线性可调。综合来看，v2 是当前版本中最适合作为最终系统和论文主结果的方案。
