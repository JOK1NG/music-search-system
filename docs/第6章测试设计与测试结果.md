# 第 6 章测试设计与测试结果写作稿

> 说明：本文档根据 `tests/` 自动化测试、`tools/e2e_search_test.py` 端到端检索脚本、`logs/` 目录中的 V2 最终版检索与诊断日志，以及《指导老师毕业论文共性问题_完整总结.md》中对第 6 章“测试目标、测试对象、测试输入、测试步骤、预期结果、实际结果、是否符合预期”的要求整理。内容可按下列小节拆分后粘贴到论文第 6 章。

## 6.1 测试目标

【适合放在第 6.1 节：系统测试概述 / 测试目标】

本章测试的主要目标是验证 AI 音乐相似度检索系统在功能完整性、安全性、音频预处理一致性、离线索引构建可靠性和实际检索效果等方面是否达到设计要求。系统的核心功能包括用户注册登录、JWT 身份认证、音频上传检索、检索历史记录、收藏管理、音频文件访问以及离线指纹库构建等。测试过程中既关注普通业务流程能否正常完成，也关注异常输入、未授权访问、超大文件上传、错误文件格式和索引构建失败等边界场景。

系统测试采用自动化单元测试与端到端业务验证相结合的方式。其中，单元测试主要用于验证后端接口、安全机制、预处理函数和离线建库流程的正确性；端到端测试通过随机抽取音乐库中的原始音频并调用 `/search` 接口，验证系统在真实检索链路中的 Top-1 命中率、Top-5 命中率和平均响应时间。通过上述测试，可以判断系统是否满足本科毕业设计中对功能可用性、运行稳定性和检索准确性的基本要求。

## 6.4 检索效果验证

【适合放在第 6.4 节：检索效果测试 / 端到端测试结果】

为了验证系统在真实业务链路中的检索效果，本文使用 `tools/e2e_search_test.py` 进行端到端测试。该脚本从 `data/raw/` 音乐库中随机抽取指定数量的音频文件，将整首音频上传至本地 FastAPI 服务的 `/search` 接口，然后检查返回结果中的 Top-1 和 Top-5 是否包含原始歌曲。该测试覆盖了音频上传、服务端临时文件处理、音频加载、滑动窗口切片、模型哈希提取、Faiss 汉明距离检索、数据库元数据查询和接口结果返回等完整流程。

本次测试使用 V2 最终生产权重 `hash_model_v2_epoch_10_best.pth` 和对应离线索引。根据 `logs/rebuild_v2_final.log`，系统对 8000 首原始音乐进行了滑动窗口指纹提取，最终生成 203200 条子指纹。根据 `logs/diag_v2_final.log`，Faiss 索引中共有 203200 条记录，每条指纹为 16 bytes，即 128 bit；songs 表中共有 203200 条 faiss_id 映射记录，平均每首歌曲约 25.4 个检索窗口。

表 6-3 端到端检索测试结果

| 测试项目 | 测试方法 | 预期结果 | 实际结果 | 是否符合预期 |
|---|---|---|---|---|

## 6.5 哈希指纹质量验证

【适合放在第 6.5 节：检索效果分析 / 模型与索引质量分析】

除端到端业务命中率外，本文还根据诊断日志对哈希指纹质量进行分析。V2 最终版本索引共包含 203200 条 128 位二进制子指纹，唯一指纹数为 192738 条，唯一率为 94.85%。同曲片段之间的平均汉明距离约为 16.92 bit，中位数为 14 bit；跨歌曲片段之间的平均汉明距离约为 61.65 bit，中位数为 62 bit；跨歌曲距离为 0 的情况为 0 对。

表 6-4 哈希指纹诊断结果

| 指标 | 实际结果 | 说明 |
|---|---:|---|
| 索引总量 | 203200 条 | 由 8000 首原始音频滑动窗口提取得到 |
| 指纹长度 | 128 bit | 每条二进制码占 16 bytes |
| 唯一指纹数 | 192738 条 | 表示大部分窗口具有可区分的哈希表示 |
| 指纹唯一率 | 94.85% | V2 版本较好地缓解了哈希坍塌问题 |
| bit-balance 平均偏差 | 0.0789 | 二进制位分布整体接近均衡，但仍存在个别偏移位 |
| 同曲平均距离 | 16.92 bit | 同一歌曲不同窗口之间保持较近距离 |
| 跨曲平均距离 | 61.65 bit | 不同歌曲之间保持较大汉明距离 |
| 跨曲 0 距离 | 0 对 | 未发现不同歌曲完全相同的 128 位指纹对 |

上述结果说明，V2 模型生成的哈希空间具有较好的区分能力：同一歌曲的不同片段在汉明空间中距离较近，不同歌曲之间距离明显拉开，且没有出现跨歌曲 0 距离完全碰撞。与此同时，诊断结果也显示 bit-balance 平均偏差仍高于理想值，跨歌曲碰撞码数量仍存在一定规模，说明模型仍有继续优化空间。综合端到端检索结果和哈希诊断结果，当前版本已经满足毕业设计系统验证要求，但对于复杂外录环境、强混响和设备底噪等物理域偏移场景，仍需要在后续研究中继续增强鲁棒性。

## 6.6 测试结果汇总

【适合放在第 6.6 节：测试结果分析 / 本章小结】

本章围绕 AI 音乐相似度检索系统的功能模块、安全机制、音频预处理、离线建库和检索效果进行了测试。自动化单元测试共执行 22 个用例，结果全部通过；端到端检索测试随机抽取 10 首原始音频进行上传检索，Top-1 命中率和 Top-5 命中率均为 100.0%，平均响应时间约为 9367 ms；离线索引共包含 203200 条 128 位子指纹，数据库映射记录与索引记录保持一致。

测试结果表明，系统能够正确完成用户注册登录、令牌认证、音频上传、相似音乐检索、收藏鉴权、历史记录鉴权、非法文件拦截和离线指纹库构建等功能。系统在原曲检索场景下具有较高准确率，能够满足数字音乐版权查重和相似度检索的基本应用需求。测试过程中发现的主要不足是端到端检索平均响应时间仍接近 9 秒，且当前验证重点集中在数字原曲和白噪音抗干扰场景，对复杂外录环境下的设备底噪、房间混响和播放录制链路失真覆盖不足。因此，后续可从模型鲁棒性训练、索引召回策略优化、服务端并发处理和外录测试集构建等方面继续改进。
